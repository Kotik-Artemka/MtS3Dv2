# MtS 3D

Сайт-агрегатор STL-моделей с интерактивной галереей. Два обычных Django-проекта: backend хранит данные и отдаёт REST API, web показывает страницу и передаёт запросы бэкенду.

## Запуск

Нужны Python 3.12 и браузер с WebGL 2. Команды выполняются из папки MtS3Dv2:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python backend/manage.py migrate
python web/manage.py migrate
python backend/manage.py createsuperuser
```

Логин и пароль администратора задаются при `createsuperuser`. Это стандартный суперпользователь Django: он сразу может входить на сайт, в Django-админку и панель DRF. Специального скрипта создания администратора нет. Существующие аккаунты сохраняются; повторно создавать их не требуется.

В двух терминалах с активированным окружением:

```powershell
# Терминал 1
python backend/manage.py runserver 127.0.0.1:8001

# Терминал 2
python web/manage.py runserver 127.0.0.1:8000
```

Сайт: http://127.0.0.1:8000/. После входа администратору доступны ссылки на http://127.0.0.1:8001/admin/ и http://127.0.0.1:8001/api/.

Миграции backend создают каталог из четырёх моделей и таблицы пользователей. В web сохранены стандартные приложения и настройки Django; его миграции создают служебные таблицы Django. Сам каталог и аккаунты сайта находятся только в базе backend, запросы к ним идут через API.

Если backend запущен на другом порту, перед запуском web задайте его адрес:

```powershell
$env:BACKEND_URL = 'http://127.0.0.1:9001'
```

## Где что находится

```text
MtS3Dv2/
    backend/
        app/
            migrations/       # создание схемы и начального каталога
            models.py         # запись STLModel и её владелец
            serializers.py    # поля API, проверка STL и данных регистрации
            views.py          # каталог, загрузка, вход, выход и выдача файлов
            urls.py           # маршруты API
            consumers.py      # уведомления об изменении каталога
            admin.py          # STLModel в стандартной админке
            apps.py
            __init__.py
        pr/                   # стандартные настройки, URLs, ASGI и WSGI
        templates/static/stl/ # STL экспонатов и пьедестала
        manage.py
    web/
        app/
            templates/app/index.html
            static/app/       # CSS, JavaScript, логотип и Three.js
            views.py          # передача HTTP-запросов бэкенду
            forms.py          # поля формы загрузки
            consumers.py      # передача WebSocket-уведомлений браузеру
            ...               # стандартные файлы Django app
        pr/
        manage.py
    requirements.txt
    README.md
    .gitignore
```

Оба settings.py построены на стандартном шаблоне `django-admin startproject` Django 5.2: сохранены приложения, middleware, шаблоны, БД, проверка паролей, локализация и статика. В конце добавлены настройки галереи: ASGI, DRF, адрес backend, путь STL и лимит загрузки.

Проверочные скрипты, тесты, исходники Blender и промежуточные материалы находятся за пределами MtS3Dv2. Они не нужны для запуска и не входят в репозиторий сайта. Миграции остаются в приложении, поскольку это стандартный механизм создания базы Django.

## Аккаунты

| Состояние | Возможности |
| --- | --- |
| Гость | Просмотр сцены, каталога и карточки |
| Пользователь | Просмотр, кнопка скачивания, добавление STL |
| Администратор | Всё перечисленное, Django-админка, панель DRF |

Регистрация и вход находятся на сайте. Используется стандартная модель User, хеширование паролей и сессии Django. Административный доступ проверяется через `is_staff`, который автоматически установлен у пользователя, созданного `createsuperuser`. Регистрация на сайте не выдаёт административные права.

Загрузка проверяет авторизацию и CSRF на сервере. JSON-каталог и прямые адреса STL публичны: браузеру нужна геометрия для просмотра. Кнопка скачивания показывается после входа и не является запретом доступа к самому файлу.

## Добавление STL

После входа нажмите «Добавить модель». Выберите STL, задайте название, категорию, описание и цвет. Можно выбрать существующую категорию или ввести новую.

Поддерживаются бинарный и текстовый STL до 100 МиБ и 2 100 000 треугольников. Проверка структуры и координат находится в serializers.py. Повреждённый файл не добавляется в каталог. Новые файлы получают имя `user-<uuid>.stl`, а запись сохраняет пользователя, выполнившего загрузку. Ошибка создания записи сопровождается удалением сохранённого файла.

Все STL хранятся в `backend/templates/static/stl/`. Начальный каталог: `part-15.stl`, `glider.stl`, `cog-6-small.stl`, `sausage-dog.stl`. Детали подставки: `environment/pedestal.stl` и `environment/pedestal-top.stl`.

В Django-админке можно изменять метаданные существующих экспонатов. Новые STL добавляются формой сайта, чтобы файл и запись создавались вместе. При удалении записи в админке файл автоматически не удаляется.

## Как устроена галерея

- `catalog.js` — поиск, категории, карточка, загрузка и получение каталога.
- `accounts.js` — интерфейс регистрации, входа и выхода.
- `model.js` — чтение STL, нормализация размера и кеш геометрии.
- `environment.js` — загрузка двух STL-деталей пьедестала.
- `studio.js` — пол, свет, материалы и тени.
- `layout.js` — расстановка площадок по кольцам с минимальным интервалом 7,6 единицы между центрами.
- `gallery.js` — общая 3D-сцена и выбор экспонатов.
- `flight.js` — свободное перемещение камеры.
- `viewer.js` — отдельный осмотр с OrbitControls.
- `vendor/` — локальная библиотека Three.js с её лицензией.

Это рабочие части 3D-интерфейса. Blender для запуска не нужен: готовые STL-пьедесталы уже входят в проект. Большая по габариту модель уменьшается для отображения; исходный STL и размер подставки сохраняются.

WASD — полёт, пробел/C — высота, Shift — ускорение. Перетаскивание мышью меняет обзор. «Управление мышью» включает захват курсора, Esc освобождает его. На сенсорном экране есть кнопки движения. В карточке можно вращать модель, приближать её и сбрасывать ракурс.

## HTTP и WebSocket

Браузер запрашивает `/api/models/`, STL и операции аккаунта у web. Представления web передают запрос backend, сохраняя сессию и CSRF. В браузерном JavaScript адрес backend не прописан.

Браузер подключается к `/ws/catalog/`. Web ретранслирует WebSocket backend. Пока соединение открыто, backend раз в две секунды проверяет метаданные и отправляет `catalog.changed` при изменении. После уведомления браузер повторно запрашивает REST-каталог. Channels и Daphne нужны для этого соединения; Redis в текущем варианте не используется.

## Перенос проекта

В Git входят код, миграции, исходные STL, статика и браузерные библиотеки. Рабочие SQLite-базы, пользовательские `user-*.stl`, окружение и кэш исключены через .gitignore. Для переноса своего каталога сохраните `backend/db.sqlite3` вместе с пользовательскими STL.

Команды runserver предназначены для локального запуска. Переменные `DJANGO_SECRET_KEY`, `DJANGO_DEBUG` и `DJANGO_ALLOWED_HOSTS` позволяют изменить настройки среды.
